# NOTE on chromadb + venv: chromadb 1.x talks to sqlite through a Rust binding,
# and a freshly created venv's python.exe copy gets a narrower Windows ACL token
# than E:\Python\python.exe.  Under that copy, chromadb fails with
# SQLITE_CANTOPEN / os error 5 even at danger-full-access.  Fix: replace the
# venv interpreter with a hardlink to the global one, then recreate the venv
# only if you are willing to redo it:
#   Remove-Item .venv\Scripts\python.exe
#   cmd /c mklink /H .venv\Scripts\python.exe E:\Python\python.exe
#

# workflow die with UnicodeDecodeError instead of auditing anything.
