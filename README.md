# start-point

个人技术主页 / 公开技术笔记

---

## 本仓库定位

start-point 是**公开仓库**，面向 GitHub 社区展示我的技术方向、精选项目和踩坑记录。

与之对应的 [dev-main](https://github.com/3315455939/dev-main) 是私人仓库——核心代码、服务器配置、运维脚本都在那里。本仓库只放可以公开的内容。

## 双库关系范式

```
dev-main (private)                 start-point (public)
┌──────────────────────┐           ┌──────────────────────┐
│ 核心代码 / 配置       │  精选 →  │ README 自我介绍       │
│ 服务器运维 / 密钥     │  脱敏 →  │ 项目展示 (摘要/截图)   │
│ 内部文档 / 交接记录   │  输出 →  │ 技术笔记 / 踩坑记录   │
│ 不公开，仅自己访问     │          │ 任何人可见            │
└──────────────────────┘           └──────────────────────┘
```

## 操作范式

### 范式 A：从 dev-main 提炼公开内容
```
1. 在 dev-main 中完成开发 / 解决一个技术问题
2. 将可公开的部分（思路、架构、截图、不涉及敏感的代码片段）写成笔记
3. 放到 start-point/notes/ 下
4. 提交推送
```

### 范式 B：独立撰写技术笔记
```
1. 直接在 start-point/notes/ 下新建 markdown 文件
2. 写完后提交推送
3. （可选）在 dev-main 中补充不公开的内部细节
```

### 范式 C：维护个人 Profile
```
1. 编辑 README.md，更新自我介绍、技能栈、项目链接
2. GitHub 会自动将本仓库 README 展示在你的 Profile 页
3. 提交推送
```

## 目录结构

```
start-point/
├─ README.md           ← 个人主页 / 入口
├─ notes/              ← 公开技术笔记
└─ projects/           ← 精选项目展示（每个项目一个 README）
```

## 红线

- ❌ 禁止放入任何 API Key、Token、密码
- ❌ 禁止放入服务器 IP、内部架构细节
- ❌ 禁止放入 dev-main 项目的完整源代码
- ✅ 每次推送前确认没有敏感信息
- ✅ 笔记中涉及内部实现时，只说思路，不放代码
